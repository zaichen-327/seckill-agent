## 一、小轮压力测试：

过程：全链路（验证码→token→秒杀），实现1线程*20循环

结果：

20次请求全绿，订单20=初始100-Redis剩余80，重复0，死信队列0



## 二、大轮压力测试：

过程：进行核心链路的测试（Lua扣库存 + MQ落库）在大量数据同时并发的情况下，通过Mq来减轻数据库的压力，避免大量订单的请求直接落库，500线程在1秒内启动，使用token预埋的方式，防止各线程之间的token互相掩埋。

结果：

500请求HTTP全200，平均26ms/最大86ms，峰值QPS440，订单500=初始2000-Redis剩余1500，实现了0超卖

幂等使用uk_user_activity的唯一约束保证一人一单，重复的请求会触发Redis的库存回补



## 三、测试总结：

在测试过程中碰到了以下问题：

1、explain数据库操作流程时发现，数据库缺少一个activityId的索引，只有userId和activityId的联合唯一索引，这会导致在查订单表时，只看单个秒杀活动的订单，但是却无法使用索引，所以我添加了一个activityId的索引，增加微小的维护成本来提高查询的订单的速率

2、测试过程中发现用户同时登录时会出现验证码相互覆盖的问题，这导致用户全部秒杀失败，添加一个UUID的验证码id放在redis里面存储，从而解决了这个问题，不过，token仍有此问题，等待之后的登录功能开发完成的测试在进行修改

## 四、修复后登录测试总结：

1、修复了token互相掩埋的问题，可以真实模拟秒杀的高并发运行

2、加入了用户的注册和登录功能，经过测试依旧保存了程序的运行能力，实现0超卖
