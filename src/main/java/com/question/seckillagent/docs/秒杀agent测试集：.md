# 秒杀agent测试集：

## 一、可以测试的：

**1、线上有正在进行的秒杀活动吗？**

期望：（1）agent必须先调用/ops/metrics或者/ops/activities，防止不调工具，编纂答案

​	    （2）判断答案与activities里面的status=RUNNING是否存在一致，防止读错数据

来源：基础能力

**2、现在MQ有没有积压？**

期望：调用/ops/metrics，看queueDepth和deadLetterDepth，报出有没有积压和数量

来源：基础能力

**3、活动到现在卖出了多少单？**

期望：调用/ops/metrics，报dbOrderCount的值

来源：基础能力

**4、为什么这个活动的redisStock会返回null**

期望：（1）先看Redis.up：false→Redis连通性问题

​	    （2）是否所有活动都是null，是→该活动没有进行库存的预热或者key拼写错误

​	    （3）单个null→先查订单数再下结论：

​			有订单且库存扣到0的→可能是售罄后key被删；

​			订单是0：活动未预热。不能凭名字和availableStock=0就判断“卖完了”

​			库存没有TTL，不会过期

来源：真实事故：在某次测试时发现Redis里面的活动值都是null

**5、订单数和库存对不上，怎么查？**

期望：

(1) 先调get_metrics看MQ队列排空了没（queueDepth>0先等排空再数）

(2) 再对账：dbOrderCount = 初始库存 − redisStock

(3) 还对不上就查死信队列和订单明细

来源：真实翻车

**6、现在系统有没有超卖？**

期望：

(1) 调get_metrics + get_orders对账：订单数 = 初始库存 − Redis剩余库存

(2) 重复订单0，死信队列空

(3) MQ没排空要先等排空再数

来源：真实翻车（10-30小轮0超卖验证流程）

**7、死信队列里有消息，说明什么？**

期望：

(1) 先调get_metrics看deadLetterDepth是多少

(2) 大于0说明有订单消息消费失败（解析失败或落库失败被basicNack）

(3) 要定位原因得看消息内容 + 消费端日志，Agent自己看不到，得告诉运维去哪查

(4) 过关标准是死信队列空

来源：基础能力题（10-30三轮验证死信队列为空才算过）

**8、订单接口怎么只返回5条，是不是接口坏了？**

期望：

(1) 先查库再怀疑代码——库里只有5条就答“库里只有5条”，不许先说接口坏了

(2) 能说出limit是上限不是保证数

来源：11-06 /ops/orders Apifox验证现场（默认limit=20，返回5条即11-01登录回归那5单test1~test5）

**9、初始库存100，Redis还剩80，但订单表只有19条，少1单去哪了？**

期望：

(1) 先等MQ队列排空再重数——异步落库在途，不是超卖/丢单

(2) 排空后20=100−80才对得上

来源：10-30对账方法 + MQ异步落库

## ***\*二、暂缓的（5道）\****

**14、JMeter显示Throughput只有1.3/s，是系统太慢吗？（暂缓）**

期望：

先问“点了Clear吗”（Summary累加不清零会把历史数据带进来）；ramp-up下测的是投放速率，不是吞吐上限

来源：真实翻车（10-30 Summary累加不清零）

暂缓原因：Agent没有JMeter工具，看不到JMeter界面；等以后给Agent喂了JMeter操作知识再加。

**15、两个用户同时领验证码，为什么会互相覆盖？（暂缓）**

期望：

根因是单活动只有一个格子seckill:captcha:{activityId}，后请求的覆盖先请求的；修复是captchaId隔离，一人一个格子seckill:captcha:{captchaId}

来源：真实翻车（10-29用户自己发现的并发覆盖bug）

暂缓原因：Agent没有验证码工具，根因是旧实现细节，prompt里没写过；把验证码隔离的设计写进system prompt后再加。

**16、按活动id统计订单数的SQL变慢了，怎么定位？（暂缓）**

期望：

(1) EXPLAIN看type

(2) 联合索引(user_id, activity_id)按activity_id查用不上最左前缀，type=index

(3) 加idx_activity_id后type=ref + Extra=Using index（覆盖索引不回表）

来源：真实翻车（10-30 EXPLAIN index→ref优化）

暂缓原因：Agent没有数据库工具，查不了EXPLAIN；以后给Agent接了数据库查询工具或喂了SQL知识再加。

**17、查10个活动的指标要调几次数据库？（暂缓）**

期望：

固定5次IO，与活动数无关（批量GROUP BY + mget），不许答10次以上

来源：11-01他亲手把N+1改成批量

暂缓原因：IO次数在接口内部，工具返回里看不到；把“批量固定5次IO”写进system prompt后再加。

**18、调接口返回404，先查什么？（暂缓）**

期望：

按顺序查项目/端口/IDEA是否重启/注解映射，再怀疑代码

来源：他踩过的原型与新项目端口混淆、IDEA未重启404

暂缓原因：查项目/端口/IDEA重启是人的操作，Agent够不着；这是给人看的排障手册，可以单独放一份排障笔记里。
